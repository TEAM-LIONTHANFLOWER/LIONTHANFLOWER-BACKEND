# #64 이메일 보관 데이터 구조.

- 기존 익명 Customer와 방문 및 기록의 소유 관계를 유지한다.
- 이메일 계정과 인증번호 요청 테이블을 추가한다. 인증 성공 이후 계정을 조회하거나 생성하는 기능은 후속 구현이다.
- 브라우저의 이메일 인증 상태는 Customer에 통합하고 별도 이메일 세션 테이블은 만들지 않는다.
- 각 기록에 선택적 이메일 계정 FK와 보관 시각을 추가한다. 신규 및 기존 기록은 기본적으로 미보관이다.
- 인증 상태 세 컬럼과 보관 상태 두 컬럼은 각각 함께 존재하거나 함께 NULL이어야 한다.
- 이메일 인증번호 원문은 저장하지 않는다. code_hash 생성 방식과 비밀키 관리는 인증 기능 구현 시 결정한다.
- 인증 목적 값, 개별 보관 대상 표현, 이메일 정규화, 유효기간, 재발송 및 시도 제한, 이메일 변경은 고정하지 않는다.
- 이번 범위는 엔티티 매핑과 migration이다. 발송 API, 인증 처리, 보관 및 복원 조회 API, Repository는 추가하지 않는다.
- 다른 이메일로의 덮어쓰기 방지 및 동시성 처리는 보관 기능 구현 시 조건부 UPDATE 또는 잠금으로 보장해야 한다. FK 하나만으로 갱신 금지까지 보장하지는 않는다.
- V10은 배포 시 Flyway가 적용한다. 공유 및 운영 DB에 직접 적용하지 않는다.

## 검증 결과.

- spotlessApply 및 Java와 테스트 소스 컴파일 완료.
- 전체 test 실행은 Docker 환경을 찾지 못해 Testcontainers 초기화에서 실패. PostgreSQL 및 MySQL migration 적용 검증은 미완료.
- git diff --check 통과. 실제 Supabase 적용 및 배포는 수행하지 않음.

## 이메일 입력 형식.

- 정규식으로 ASCII 이메일 형식, 로컬파트 64자 이하, 전체 255자 이하를 검증한다. 앞뒤 공백, 연속 점, 잘못된 도메인을 거절한다.
- 계정 및 인증 요청 생성과 JPA 저장 및 갱신 시 공통 검증을 실행한다. 실제 메일 소유 확인은 인증번호 처리에서 별도로 구현한다.
- 대소문자 통합 및 자동 정규화 정책은 도입하지 않는다. 국제화 이메일 및 따옴표 로컬파트는 현재 입력 형식에서 지원하지 않는다.

## Docker 활성화 후 재검증.

- spotlessApply test --rerun-tasks --stacktrace --no-daemon 통과.
- 총 308개 테스트, 실패 0개. PostgreSQL 및 MySQL에서 V10 migration과 JPA 매핑 및 제약조건 확인 테스트 통과.
- 이메일 형식 정상 및 오류 입력과 길이 경계 테스트 통과.
- 실제 Supabase 적용 및 메일 발송 API 구현은 수행하지 않음.

## 최종 범위.

- 실패 횟수 상한은 미정으로 되돌린다. V11 및 5회 제한 코드와 테스트를 제거하고 V10까지만 포함한다.
- failed_attempts 컬럼과 음수 금지 제약조건은 유지한다. 인증 시도 횟수 증가 및 차단 로직은 후속 API 구현 시 정책에 맞춰 추가한다.

- V11 제거 후 spotlessApply spotlessCheck test --stacktrace --no-daemon 통과. 총 308개 테스트, 실패 0개.
