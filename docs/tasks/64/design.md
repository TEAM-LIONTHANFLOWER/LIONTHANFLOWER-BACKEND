# #64 이메일 보관 데이터 구조.

- 기존 익명 Customer와 방문 및 기록의 소유 관계를 유지한다.
- 이메일 계정과 인증번호 요청 테이블을 추가한다. 인증 성공 이후 계정을 조회하거나 생성하는 기능은 후속 구현이다.
- 브라우저의 이메일 인증 상태는 Customer에 통합하고 별도 이메일 세션 테이블은 만들지 않는다.
- 각 기록에 선택적 이메일 계정 FK와 보관 시각을 추가한다. 신규 및 기존 기록은 기본적으로 미보관이다.
- 인증 상태 세 컬럼과 보관 상태 두 컬럼은 각각 함께 존재하거나 함께 NULL이어야 한다.
- 이메일 인증번호 원문은 저장하지 않는다. code_hash 생성 방식과 비밀키 관리는 인증 기능 구현 시 결정한다.
- 인증 목적 값, 개별 보관 대상 표현, 유효기간, 재발송 및 시도 제한, 이메일 변경은 고정하지 않는다.
- 이번 범위는 엔티티 매핑과 migration이다. 발송 API, 인증 처리, 보관 및 복원 조회 API, Repository는 추가하지 않는다.
- 다른 이메일로의 덮어쓰기 방지 및 동시성 처리는 보관 기능 구현 시 조건부 UPDATE 또는 잠금으로 보장해야 한다. FK 하나만으로 갱신 금지까지 보장하지는 않는다.
- V10은 배포 시 Flyway가 적용한다. 공유 및 운영 DB에 직접 적용하지 않는다.

## 검증 결과.

- spotlessApply 및 Java와 테스트 소스 컴파일 완료.
- 전체 test 실행은 Docker 환경을 찾지 못해 Testcontainers 초기화에서 실패. PostgreSQL 및 MySQL migration 적용 검증은 미완료.
- git diff --check 통과. 실제 Supabase 적용 및 배포는 수행하지 않음.

## 이메일 입력 형식.

- 정규식으로 ASCII 이메일 형식, 로컬파트 64자 이하, 전체 255자 이하를 검증한다. 앞뒤 공백, 연속 점, 잘못된 도메인을 거절한다.
- 계정 및 인증 요청 생성과 JPA 저장 및 갱신 시 공통 검증을 실행한다. 실제 메일 소유 확인은 인증번호 처리에서 별도로 구현한다.
- 도메인만 Locale.ROOT로 소문자로 정규화하며 로컬파트는 그대로 보존한다. 계정 생성 및 인증 요청 생성과 JPA 저장/갱신에서 같은 기준을 적용한다. 국제화 이메일 및 따옴표 로컬파트는 지원하지 않는다.

## 이메일 도메인 정규화 리뷰 반영.

- 정규화한 값을 기존 email UNIQUE 제약조건으로 검증한다. V10은 수정하지 않는다. 후속 V11에서 도메인 소문자 DB 제약조건을 추가한다.
- 계정 및 인증 요청 생성 시 도메인 대소문자 동일성, 로컬파트 보존, 멱등성을 검증한다. PostgreSQL 및 MySQL에서 두 계정 저장 시 중복 거절을 검증한다.
- 이미 저장된 대문자 도메인 및 중복 계정의 일괄 정리는 수행하지 않는다. 운영 데이터가 있다면 배포 전 점검 및 별도 데이터 migration이 필요하다.

## DB 도메인 제약조건.

- V11__enforce_lowercase_email_domains.sql에서 계정과 인증 요청의 이메일 도메인에 소문자 ASCII 도메인만 허용한다. REGEXP_LIKE의 c 플래그로 MySQL의 대소문자 비구분 collation에서도 대문자 입력을 거절한다.
- DB는 대문자를 자동 변환하지 않고 거절한다. 앱은 기존 normalize로 소문자로 변환한 뒤 저장한다. 로컬파트는 보존한다.
- 직접 INSERT 및 UPDATE의 대문자 거절, 소문자 허용, 기존 UNIQUE 중복 거절을 PostgreSQL/MySQL에서 테스트한다.
- 기존 대문자 데이터가 있다면 새 제약조건 적용이 실패할 수 있다. 고객/기록을 임의 병합하지 않으며 배포 전 점검과 별도 정리가 필요하다.
- 실패 횟수 상한은 여전히 미정이다. 이번 V11은 정규화 제약조건만 추가한다.

- V11 제약조건 추가 후 전체 테스트 314개, 실패 0개. 두 DB에서 직접 SQL 제약 및 중복 거절 검증 통과.
