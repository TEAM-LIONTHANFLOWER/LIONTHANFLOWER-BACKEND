# ADR-001. 익명 세션과 직원 단말 인증

- 상태. Accepted
- 결정일. 2026-08-14
- 범위. 고객 세션, 직원 접근 경계, 초기 MVP 인증 모델

## 문맥

해커톤 MVP에서는 Google 로그인과 직원 PIN 인증을 도입하지 않고 고객과 직원 모두 빠르게 서비스를 이용해야 한다. 고객은 매장 QR로 진입해 언어, 응대 방식, Myself와 Arc 기능을 사용한다. 직원은 별도 계정으로 로그인하지 않고 매장 단말에서 고객을 선택해 응대를 진행한다.

로그인 없이 고객의 방문과 Arc를 구분하려면 브라우저에 저장되는 익명 식별자가 필요하다. 직원 접근은 일반 고객 브라우저와 분리된 매장 단말 단위의 인증 경계가 필요하다.

## 결정

### 고객 식별

- 첫 매장 QR 진입 시 서버가 예측할 수 없는 익명 토큰을 발급한다.
- 브라우저에는 원본 토큰을 쿠키로 저장하고, 데이터베이스에는 토큰의 해시만 저장한다.
- `Customer.tokenHash`를 같은 브라우저의 고객 식별자로 사용한다.
- 고객의 Arc 조회와 현재 Visit 접근은 고객 쿠키에서 확인한 고객 식별자와 대상 리소스의 `customerId`를 비교한다.
- Google OAuth, 고객 비밀번호, 고객 PIN은 MVP 범위에 포함하지 않는다.

### 직원 접근

- 직원은 로그인 계정이 아니라 매장에 사전 등록된 `Staff` 프로필로 관리한다.
- 직원용 매장 단말은 `StoreDevice`로 관리하고, 단말 토큰의 원본이 아닌 해시만 `StoreDevice.tokenHash`에 저장한다.
- 직원은 활성화된 같은 매장의 단말에서 직원 목록 중 자신의 프로필을 선택한다.
- 직원 API 접근은 인증된 활성 단말을 기준으로 판단하고, 선택된 직원·단말·방문이 같은 매장에 속하는지는 Application Service에서 검증한다.
- 직원 PIN 인증과 별도 직원 로그인은 MVP 범위에 포함하지 않는다.

### 세션 수명과 보안 경계

- 고객 식별 쿠키와 직원 단말 인증 토큰은 서로 다른 목적과 저장 공간을 사용한다.
- 토큰 원본은 로그와 데이터베이스에 남기지 않는다.
- 쿠키 삭제 또는 기기 변경으로 고객 식별자를 잃은 경우 기존 고객 기록 복구는 지원하지 않는다.
- 토큰 발급, 쿠키 속성, 만료, 폐기, 요청 필터는 이후 Application·Security 계층에서 구현한다. 이번 ADR과 도메인 엔티티는 식별자 해시를 저장하는 모델만 정의한다.

## 대안

### Google OAuth와 고객·직원 계정 도입

일반적인 계정 복구와 재방문 식별에는 유리하지만, 매장 QR 기반의 짧은 MVP 흐름에 로그인 화면과 계정 관리가 추가된다. 해커톤의 핵심 매칭 흐름보다 인증 구축 비용이 커지므로 채택하지 않았다.

### 직원 QR 스캔만으로 직원 접근 허용

구현은 단순하지만 QR이 노출되면 직원 권한이 탈취될 수 있다. 현재 결정은 매장 단말을 별도 인증 주체로 두어 직원 API 접근 경계를 먼저 만든다.

## 결과

### 장점

- 고객은 로그인 없이 QR 진입 직후 서비스를 사용할 수 있다.
- 직원은 PIN이나 계정 입력 없이 단말에서 직원을 선택해 고객을 응대할 수 있다.
- 원본 토큰을 저장하지 않아 데이터베이스 유출 시 직접적인 세션 토큰 노출을 줄인다.

### 비용과 제한

- 쿠키 삭제와 기기 변경 후 고객의 이전 Arc를 자동으로 복구할 수 없다.
- 직원 계정·역할·권한 등급이 없으므로 운영 환경에 필요한 세밀한 권한 제어를 제공하지 않는다.
- 단말 토큰 발급과 폐기, 쿠키 탈취 대응, 만료 정책은 별도 Security 구현이 필요하다.
- 해커톤 MVP의 편의성을 우선한 결정이므로 운영 출시 전에는 직원 인증과 고객 계정 복구를 재검토해야 한다.
