# ADR-001. 익명 세션과 직원 개인 기기 인증

- 상태. Accepted
- 결정일. 2026-08-15
- 범위. 고객 익명 식별, 직원 프로필과 개인 기기 인증 모델

## 문맥

해커톤 MVP에서는 고객 로그인과 직원 계정 관리 없이 매장 QR 진입과 오프라인 응대를 빠르게 제공한다. 고객은 브라우저 토큰으로 자신의 방문과 Arc를 다시 식별하고, 직원은 본인의 개인 기기에서 사전 등록된 프로필로 서비스를 사용한다.

## 결정

### 고객 식별

- 첫 QR 진입 시 서버가 예측할 수 없는 익명 브라우저 토큰을 발급한다.
- 브라우저에는 원본 토큰을 저장하고, 데이터베이스에는 토큰 해시만 `Customer.tokenHash`로 저장한다.
- 같은 브라우저 토큰의 해시가 있으면 기존 `Customer`를 사용하고, 없으면 새 고객을 만든다.
- 초기 설정에서 기존 `Customer.name`을 미리 채우며, 다른 이름을 입력하면 고객 이름을 갱신한다.
- 쿠키를 삭제하거나 다른 기기를 사용하면 기존 고객을 복구하지 않는다.

### 직원 프로필과 개인 기기

- 직원은 `Staff` 한 행과 개인 기기의 토큰 해시를 영구적인 1:1 관계로 사용한다.
- `Staff.tokenHash`는 원본 토큰이 아닌 해시이며 유일해야 한다.
- 직원 프로필에는 근무 매장 UUID, 이름과 복수 구사 언어를 저장한다.
- 구사 언어는 `EN`, `ZH`, `JA`, `RU` 중 하나 이상을 선택하지만 직원 매칭이나 화면 필터에는 사용하지 않는다.
- 직원 프로필 수정, 비활성화, 기기 복구와 직원 등록 접근 통제는 해커톤 범위에서 제외한다.
- 별도의 `StoreDevice` 엔티티는 두지 않는다.

### 구현 경계

- 토큰 발급, 쿠키 속성, 만료와 요청 필터는 이후 Application·Security 계층에서 구현한다.
- 이번 이슈는 익명 토큰 해시와 직원 개인 기기 토큰 해시를 저장하는 도메인 모델만 확정한다.
- 직원과 방문의 같은 매장 여부, 직원 등록 권한과 실제 요청 주체 검증은 Application Service의 후속 책임이다.

## 대안

### 고객·직원 계정과 OAuth 도입

계정 복구에는 유리하지만 QR 기반 해커톤 흐름에 로그인과 계정 관리가 추가된다. MVP에서는 익명 고객 토큰과 사전 등록 직원 프로필을 선택한다.

### StoreDevice를 별도 인증 주체로 유지

매장 공용 단말과 선택 직원을 분리할 수 있지만, 승인된 IA는 직원 개인 기기와 영구적인 1:1 관계를 요구한다. 따라서 `StoreDevice`를 제거하고 직원에 토큰 해시를 둔다.

## 결과

### 장점

- 고객은 로그인 없이 QR 진입 후 같은 브라우저에서 자신의 방문을 이어갈 수 있다.
- 직원은 공용 단말 선택 절차 없이 개인 기기와 프로필로 응대를 시작할 수 있다.
- 데이터베이스에는 원본 토큰이 남지 않는다.

### 비용과 제한

- 쿠키 삭제와 기기 변경 후 고객의 기존 기록을 복구할 수 없다.
- 직원 등록 접근 통제와 기기 복구가 없으므로 운영 출시 전 별도 인증 설계가 필요하다.
- 직원 언어 정보는 저장만 하며 자동 매칭 품질을 높이지 않는다.
